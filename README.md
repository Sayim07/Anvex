# Anvex

## AI-Based Cyber Threat Detection

Anvex is a passive network monitoring and explainable threat intelligence platform designed to detect cyber threats in near real time.

The system uses network metadata and machine learning to detect six major threat categories while maintaining passive, read-only network monitoring with zero payload decryption.

---

## 🎯 Objective

The objective of Anvex is to analyze network traffic metadata and identify suspicious behavior across multiple cyber-threat categories.

The system provides:

- Passive network monitoring
- Near real-time threat detection
- Machine-learning-based analysis
- Statistical threat detection
- Explainable AI using SHAP
- Standardized threat alerts
- Immutable forensic auditing using blockchain
- Real-time SOC visualization

---

## 🏗️ System Architecture

The overall pipeline is:

```text
Network Traffic
        ↓
Synthetic Traffic / PCAP Replay
        ↓
Passive Packet Ingestion
        ↓
Zeek Metadata Extraction
        ↓
Kafka / Redis Streaming
        ↓
AI/ML Threat Detection Engine
        ↓
Threat Scoring + SHAP Explainability
        ↓
Standardized Alert JSON
        ↓
SOC Dashboard + Blockchain Audit
```

---

## 🚨 Threats Detected

Anvex is designed to detect six threat vectors:

1. DDoS
2. Port Scanning
3. DGA / DNS Tunneling
4. JA4 / Encrypted Malware Profiling
5. C2 Beaconing
6. Data Exfiltration

---

## 🤖 AI/ML Engine

The AI/ML engine analyzes structured network metadata generated by Zeek.

### Machine Learning

The planned machine-learning components include:

- XGBoost
- Isolation Forest

### Statistical Analysis

The system uses statistical techniques including:

- Shannon Entropy
- FFT-based periodicity analysis
- Inter-Arrival Time variance
- Traffic volume baselines

### Explainable AI

SHAP is used to calculate feature attribution values so that detected threats can include evidence explaining why the model produced a prediction.

---

## 🔍 Feature Engineering

The detection engine uses features such as:

### DDoS

- Source-IP Shannon Entropy
- SYN/ACK Ratio
- Packets Per Second (PPS)

### Port Scan

- Destination Port Fan-out
- Connection Failure Rate

### DGA / DNS Tunneling

- N-gram Character Probabilities
- Subdomain Entropy

### JA4 / Encrypted Malware

- JA4 / JA3 Fingerprints
- SPLT (Packet Size / Timing)

### C2 Beaconing

- Inter-Arrival Time (IAT) Variance
- FFT Periodicity

### Data Exfiltration

- Outbound-to-Inbound Byte Ratio
- Traffic Volume Baselines

---

## 📥 Data Pipeline

The system follows a passive ingestion architecture.

Zeek converts captured network packets into structured metadata logs, including:

- `conn.log`
- `dns.log`
- `ssl.log`

These events are streamed through Apache Kafka or Redis Streams before being processed by the AI/ML detection engine.

---

## 📤 Threat Alert

The AI engine produces a standardized JSON alert containing information such as:

- Threat type
- Threat severity
- Detection confidence
- Detector scores
- Extracted features
- Explainability information

The alert is then consumed by the backend and SOC dashboard.

## ⛓️ Blockchain Forensic Audit

Detected alerts can be hashed using SHA-256 and notarized on a local EVM-based blockchain.

The blockchain layer is intended to provide a tamper-evident forensic audit trail.

Technologies include:

- Solidity
- Hardhat / Anvil
- Web3.py
- Ethers.js

## 🔄 Development Workflow

The project follows a sequential pipeline:

1. Network traffic is generated or replayed.
2. Network packets are passively captured.
3. Zeek converts traffic into structured metadata.
4. Events are streamed through Kafka / Redis.
5. The AI/ML engine extracts features and detects threats.
6. Threat scores and SHAP explanations are generated.
7. A standardized alert JSON is produced.
8. The backend sends the alert to the SOC dashboard.
9. The alert can be hashed and recorded on the blockchain.
